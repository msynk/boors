# Iranian capital-market data: implementation-level details (Codal taxonomy, TSETMC filter language, TSETMC/fipiran/tgju field semantics)

Research date: 2026-10-17. Live JSON samples below were fetched on that date (Jalali 1405/07/25). Anything marked **(inferred)** is my reading of values, not a documented statement.

## Key Question 1: Codal letter taxonomy (LetterType / Category codes, title patterns, monthly-report structure)

### Takeaway
Codal's own lookup endpoint `https://search.codal.ir/api/search/v1/categories` is the authoritative source: it returns Category codes (1 annual FS, 2 material disclosure, 3 monthly performance, 5 board, 6 AGM, 7 capital increase, ...) with nested LetterType `Id`s (58 monthly activity, 6 interim/annual FS, 11 material disclosure, 16/18 AGM invitations, 20/21/22 AGM decisions, 55/56/53/27/28/119 capital-increase stages, 30 DPS schedule, 32 board activity report). "گزارش تفسیری مدیریت" and the "گروه الف/ب" split are **not** letter types: the A/B class is encoded in the Title of LetterType 11, and the interpretive report is not a separate letter at all. The monthly activity report page embeds a `var datasource = {...}` JSON (sheets → tables → cells with rowCode/columnCode/periodEndToDate); the manufacturing template "گزارش فعالیت ماهانه تولیدی - V4" has tables BuyRawMaterial (3464), ProductionAndSales (3465), Energy (3466), SourceUsesCurrency (3640).

### Inferences
- The `let=` query parameter in `Url` equals the LetterType `Id`; `ct` and `ft` seem to be child-type/file-type selectors (ft=1005 for PDF in `PdfUrl`; `ft=2` with `ct=5` appeared on some ن-10 pages) **(inferred from URL samples)**.
- "گزارش تفسیری مدیریت" is published as an attachment under ن-10 letters rather than as a LetterType; matching should use the ن-10 letter's `Attachment.aspx` listing and filter attachment titles by regex `تفسیری` **(inferred: absent from the categories endpoint and from the sampled attachment list)**.
- Group A vs B of material disclosures must be parsed from `Title` with a regex tolerant of `-` vs `–` before `گروه (الف|ب)`, e.g. `افشای اطلاعات بااهمیت - \((?P<subject>.+?) [-–] گروه (?P<group>الف|ب)\) منتهی به سال مالی (?P<fy>[۰-۹/]+)` **(inferred pattern from 16 sampled titles)**.
- Capital-increase "stages" for a timeline can be ordered 23 → 24 → 55/80/56 → 45 → 53 → 57 → 25 → 27 → 119 → 28 → 164, by the semantics of their names **(inferred ordering)**.

## Key Question 2: TSETMC market-watch filter language (فیلترنویسی دیده‌بان)

### Takeaway
TSETMC's own help pages (old.tsetmc.com, ParTree=151715, LnkIdn 3196–3199) define the variables: parenthesised current fields `(l18) (l30) (tno) (tvol) (tval) (py) (pf) (pmin) (pmax) (pl) (plc) (plp) (pc) (pcc) (pcp) (eps) (pe) (tmin) (tmax) (z) (mv) (bvol) (cs) (buyop) (predtran)`, order-book levels 1–5 `(pd#) (zd#) (qd#) (po#) (zo#) (qo#)`, client-type object `(ct).Buy_CountI/Buy_CountN/Buy_I_Volume/Buy_N_Volume/Sell_CountI/Sell_CountN/Sell_I_Volume/Sell_N_Volume`, history array `[ih][n].PClosing/PDrCotVal/ZTotTran/QTotTran5J/QTotCap/PriceMin/PriceMax/PriceYesterday/PriceFirst` (n days ago, `[ih][0]` = yesterday) and statistics `[is1]..[is89]`. Expressions are JavaScript (`&&`, `||`, `Math.*`, `true==function(){...}()`). No official source defines an `(ob1).Buy_Qty_1` style object; the order book is addressed via `pd/qd/zd/po/qo/zo`.

### Cited Findings

**Client-type object (official help, LnkIdn=3198)** — [old.tsetmc.com 3198](https://old.tsetmc.com/Site.aspx?ParTree=151715&LnkIdn=3198):

**Operators, functions, syntax (community mirror of the official guide)** — [bourse-trader.ir/tsetmc](https://bourse-trader.ir/tsetmc); [amozeshebourse.ir راهنمای فیلتر نویسی](https://amozeshebourse.ir/%D8%B1%D8%A7%D9%87%D9%86%D9%85%D8%A7%DB%8C-%D9%81%DB%8C%D9%84%D8%AA%D8%B1-%D9%86%D9%88%DB%8C%D8%B3%DB%8C/):

### Inferences
- The filter variable set is the market-watch row schema: `(cs)` = `cSecVal`, `(z)` = `zTitad`, `(tmin)/(tmax)` = `psGelStaMin/psGelStaMax`, `(bvol)` = `baseVol`, `[ih][n].*` = the `GetClosingPriceDailyList` fields (`pClosing, pDrCotVal, zTotTran, qTotTran5J, qTotCap, priceMin, priceMax, priceYesterday, priceFirst`), `(ct).*` = `GetClientType` fields (`buy_I_Volume, buy_N_Volume, buy_CountI, ...`) **(inferred from identical field names across 5j9 parsers and GetInstrumentInfo/GetClosingPriceInfo JSON)**.
- A compatible engine can be built as a sandboxed JS evaluator exposing: scalar getters for the 3196 list, arrays `pd[1..5]` etc., object `ct`, array `ih` (index 0 = previous day), array `is[1..90]`, plus `Math`; `[ih]` should be loaded lazily (60 rows) and `ct`/`is` on demand, mirroring TSETMC's `read_client_type`/`fill_data` flags **(inferred design)**.

### Gaps

### Inferences
- GetMarketWatch compact-key semantics **(inferred by matching values against GetClosingPriceInfo/GetInstrumentInfo and the 5j9 MarketWatchInit column order)**: `lva`=l18 symbol, `lvc`=l30 name, `pdv`=pl (last price, pDrCotVal), `pcl`=pc (closing), `py`=yesterday, `pf`=first, `pmn/pmx`=day min/max, `pMin/pMax`=static thresholds tmin/tmax (وسپهر: 5080×0.97≈4930, ×1.03≈5230), `qtj`=tvol (qTotTran5J), `qtc`=tval (qTotCap), `ztt`=tno (zTotTran), `bv`=baseVol, `vc`=visit count, `csv`=cSecVal, `ztd`=zTitad shares, `insID`=instrumentID, `pmd/pmo`=best bid/ask price (pd1/po1), `pc` and `pcpc` both equal `pcl − py` in the samples (one is the closing change, the other probably the last-price change; indistinguishable because pdv==pcl in both samples), `hEven`=last trade time HHMMSS; `blDs[]` = best limits where `n`=level, `qmd/zmd/pmd`=bid qty/count/price (MeDem = demand), `pmo/zmo/qmo`=ask price/count/qty (MeOf = offer), `rid`=ref id for `RefID` incremental polling. The long-name fields (`pClosing, pDrCotVal, zTotTran, ...`) are present but zero in the market-watch rows.
- `hEven`/`RefID` parameters implement incremental updates (as `h`/`r` do for the legacy `MarketWatchPlus.aspx`, rounded to 5 and 25 by 5j9); passing 0/0 returns the full snapshot **(inferred)**.
- `yVal` is the instrument type: 300 = بورس common stock, 303 = فرابورس common stock, 305 = ETF/fund unit, 320 = option, 208 = corporate sukuk (debt), 400 = rights; search snippets add 301 participation bonds, 304 futures, 309 base-market/test, 403 rights on ETF **(300/303/305/320/208/400 verified live; others from snippets/tse-client)**.
- `flow` = market: 1 بورس, 2 فرابورس, 3 مشتقه (options and sukuk). Base-market (پایه) instruments were not sampled; tse-client's `m=4` suggests flow 4 = پایه **(inferred, unverified)**.
- `cgrValCot` = board/sub-market code with `cgrValCotTitle` the Persian name; letters N* are بورس boards (N1 اول/تابلوی اصلی, N2 دوم, N4 بدهی/چهارم, NS سرمایه‌گذاری حرفه‌ای), Z1/1Z فرابورس boards, H1/51 ETF boards, 13 derivatives, 17 فرابورس sukuk **(inferred from samples)**.
- `cComVal` (values "1","3","4","8","9") appears to be an instrument-class code (1/3 stocks, 4 ETF, 8 option, 9 sukuk) **(inferred; undocumented)**.
- tgju codes `sekeb` = سکه بهار آزادی (طرح قدیم), `nim` = نیم سکه, `rob` = ربع سکه, `gerami` = سکه گرمی, `mesghal` = مثقال طلا, `ons` = انس جهانی (USD), `retail_sekee` = retail Emami coin quote **(inferred from naming and price magnitudes; only `sekee` title verified)**.
